# React Web: State Management with Redux Toolkit

Use **Redux Toolkit** (`@reduxjs/toolkit` + `react-redux`) for all shared and cross-component application state. This is the standardized approach across B1Codes React projects — analogous to `flutter_bloc` on Flutter and TCA on SwiftUI.

## Core Concepts

- **Slice** — a self-contained piece of state plus the reducers and actions that mutate it, created with `createSlice`
- **Store** — the single source of truth holding every slice's state, created with `configureStore`
- **Action** — a plain object describing what happened, auto-generated by `createSlice` from your reducer names
- **Selector** — a function that reads a piece of state out of the store, used via `useAppSelector`

```
Component dispatches Action → Slice reducer mutates draft state → Store updates → useAppSelector re-renders subscribers
```

**Rule of thumb:** Use `useState`/`useReducer` for state that is genuinely local to one component and has no other consumers (an input's draft value, a dropdown's open/closed flag). Anything read or mutated by more than one component, anything that needs to survive navigation, or anything fetched from a server belongs in a Redux slice.

## Defining a Slice

`createSlice` uses Immer internally — reducers may "mutate" `state` directly; Immer produces the immutable update for you.

```ts
// features/counter/store/counterSlice.ts
import { createSlice, type PayloadAction } from '@reduxjs/toolkit';

interface CounterState {
  value: number;
}

const initialState: CounterState = { value: 0 };

const counterSlice = createSlice({
  name: 'counter',
  initialState,
  reducers: {
    incremented: (state) => {
      state.value += 1;
    },
    decremented: (state) => {
      state.value -= 1;
    },
    incrementedBy: (state, action: PayloadAction<number>) => {
      state.value += action.payload;
    },
  },
});

export const { incremented, decremented, incrementedBy } = counterSlice.actions;
export default counterSlice.reducer;
```

**Rules:**
- Name actions as past-tense events (`incremented`, not `increment`) — an action describes something that already happened, not a command.
- Keep slice state serializable (plain objects, arrays, primitives). Never store class instances, functions, `Map`/`Set`, or non-plain values — Redux DevTools and `redux-persist` both assume a serializable tree.
- One slice per feature/domain. A `cartSlice` should not know about authentication.

## Configuring the Store and Typed Hooks

Create the store once, at the app root, and export typed `useAppDispatch`/`useAppSelector` hooks so components never import the untyped `react-redux` versions directly.

```ts
// core/store/index.ts
import { configureStore } from '@reduxjs/toolkit';
import counterReducer from '@/features/counter/store/counterSlice';
import { api } from '@/core/store/api';

export const store = configureStore({
  reducer: {
    counter: counterReducer,
    [api.reducerPath]: api.reducer,
  },
  middleware: (getDefaultMiddleware) => getDefaultMiddleware().concat(api.middleware),
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

```ts
// core/store/hooks.ts
import { useDispatch, useSelector } from 'react-redux';
import type { RootState, AppDispatch } from './index';

export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();
```

```tsx
// main.tsx
import { Provider } from 'react-redux';
import { store } from '@/core/store';

createRoot(document.getElementById('root')!).render(
  <Provider store={store}>
    <App />
  </Provider>,
);
```

## Consuming State in Components

```tsx
import { useAppDispatch, useAppSelector } from '@/core/store/hooks';
import { incremented, decremented } from '../store/counterSlice';

export function Counter() {
  const count = useAppSelector((state) => state.counter.value);
  const dispatch = useAppDispatch();

  return (
    <div>
      <button onClick={() => dispatch(decremented())}>-</button>
      <span>{count}</span>
      <button onClick={() => dispatch(incremented())}>+</button>
    </div>
  );
}
```

Select the narrowest slice of state a component needs — `useAppSelector` re-renders the component whenever the selected value changes (by reference), so selecting `state.counter` instead of `state.counter.value` causes unnecessary re-renders whenever any field on `counter` changes.

## Server State: RTK Query

**RTK Query (`@reduxjs/toolkit/query/react`) is the standard for server state** — it supersedes hand-rolled `useState` + `useEffect` fetching and third-party cache libraries (TanStack Query, SWR). It ships as part of the toolkit you're already standardized on, integrates with Redux DevTools, and generates typed hooks automatically.

```ts
// core/store/api.ts
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';
import type { User } from '@/features/users/types';

export const api = createApi({
  reducerPath: 'api',
  baseQuery: fetchBaseQuery({ baseUrl: '/api/' }),
  tagTypes: ['User'],
  endpoints: (build) => ({
    getUsers: build.query<User[], void>({
      query: () => 'users',
      providesTags: ['User'],
    }),
    updateUser: build.mutation<User, Partial<User> & { id: string }>({
      query: ({ id, ...patch }) => ({ url: `users/${id}`, method: 'PATCH', body: patch }),
      invalidatesTags: ['User'],
    }),
  }),
});

export const { useGetUsersQuery, useUpdateUserMutation } = api;
```

```tsx
function UserList() {
  const { data: users, isLoading, error } = useGetUsersQuery();

  if (isLoading) return <Spinner />;
  if (error) return <ErrorView message="Failed to load users" />;
  return <ul>{users!.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

Reach for `createAsyncThunk` inside a slice instead of RTK Query only for flows that aren't a simple cache-around-a-request — a multi-step submission process, an action with side effects beyond fetching, or logic that needs to read other slice state mid-flight.

## Testing

Test slice reducers as pure functions — no store or component required.

```ts
import counterReducer, { incremented } from './counterSlice';

test('incremented increases value by 1', () => {
  const state = counterReducer({ value: 0 }, incremented());
  expect(state.value).toBe(1);
});
```

Test components with React Testing Library, wrapped in a real `Provider` backed by a fresh `configureStore()` per test (not the app's singleton store) so tests don't leak state between each other.

```tsx
function renderWithStore(ui: React.ReactElement, preloadedState?: Partial<RootState>) {
  const store = configureStore({ reducer: rootReducer, preloadedState });
  return render(<Provider store={store}>{ui}</Provider>);
}
```

## Best Practices

- **Never mutate state outside a slice's reducers.** Immer's draft mutation only works inside `createSlice`/`createReducer` — mutating state anywhere else is a real, silent bug.
- **Derive, don't duplicate.** If a value can be computed from existing state, compute it in a selector (`createSelector` from `@reduxjs/toolkit` for memoized derived data) rather than storing it redundantly and keeping both in sync.
- **Keep Context for truly global, low-frequency, non-transactional values** (theme, locale) — not as a substitute for a slice. Once a value has real transitions or is written from more than one place, it belongs in Redux.
- **Normalize collections.** Store lists of entities as `{ ids: string[], entities: Record<string, T> }` (see `createEntityAdapter`) rather than raw arrays once a feature needs lookup-by-id or frequent updates to individual items.
- **Don't put non-serializable values in actions or state** — file objects, promises, class instances. If you must pass one through a thunk, keep it out of anything reaching the store.

## Directory Placement

One slice file per feature, following the feature-first layout already used in this module (see `directory-structure.md`):

```
features/auth/
  store/
    authSlice.ts        # createSlice: state, reducers, actions
  services/
    authService.ts       # only if not modeled as an RTK Query endpoint
  pages/
    LoginPage.tsx
  components/
    LoginForm.tsx
core/
  store/
    index.ts              # configureStore, RootState/AppDispatch types
    hooks.ts               # useAppDispatch/useAppSelector
    api.ts                  # createApi — shared RTK Query base, feature endpoints injected via injectEndpoints
```
