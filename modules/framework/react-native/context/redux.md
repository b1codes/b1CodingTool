# React Native (Expo): State Management with Redux Toolkit

Use **Redux Toolkit** (`@reduxjs/toolkit` + `react-redux`) for all shared and cross-screen application state. This is the standardized approach across B1Codes React projects — the same as React Web (see the `react-web` module's `redux.md`) and analogous to `flutter_bloc` on Flutter and TCA on SwiftUI.

## Core Concepts

- **Slice** — a self-contained piece of state plus the reducers and actions that mutate it, created with `createSlice`
- **Store** — the single source of truth holding every slice's state, created with `configureStore`
- **Action** — a plain object describing what happened, auto-generated by `createSlice` from your reducer names
- **Selector** — a function that reads a piece of state out of the store, used via `useAppSelector`

```
Screen dispatches Action → Slice reducer mutates draft state → Store updates → useAppSelector re-renders subscribers
```

**Rule of thumb:** Use `useState`/`useReducer` for state genuinely local to one screen/component (a form field's draft value, a modal's open/closed flag). Anything read by more than one screen, anything that must survive navigation between routes, or anything fetched from a server belongs in a Redux slice — this replaces the ad hoc Zustand stores seen in older code.

## Defining a Slice

Identical API to React Web — `createSlice` uses Immer, so reducers "mutate" `state` directly.

```ts
// src/features/auth/store/authSlice.ts
import { createSlice, type PayloadAction } from '@reduxjs/toolkit';
import type { AuthUser } from '../types';

interface AuthState {
  user: AuthUser | null;
  isAuthenticated: boolean;
}

const initialState: AuthState = { user: null, isAuthenticated: false };

const authSlice = createSlice({
  name: 'auth',
  initialState,
  reducers: {
    signedIn: (state, action: PayloadAction<AuthUser>) => {
      state.user = action.payload;
      state.isAuthenticated = true;
    },
    signedOut: (state) => {
      state.user = null;
      state.isAuthenticated = false;
    },
  },
});

export const { signedIn, signedOut } = authSlice.actions;
export default authSlice.reducer;
```

**Rules:** name actions as past-tense events, keep state serializable, one slice per feature/domain — see `redux.md` in `react-web` for the full rationale; it applies unchanged here.

## Configuring the Store and Typed Hooks

Same pattern as web. Provide the store from the Expo Router **root layout**, above the navigator, so it wraps every route.

```ts
// src/core/store/index.ts
import { configureStore } from '@reduxjs/toolkit';
import authReducer from '@/features/auth/store/authSlice';
import { api } from '@/core/store/api';

export const store = configureStore({
  reducer: {
    auth: authReducer,
    [api.reducerPath]: api.reducer,
  },
  middleware: (getDefaultMiddleware) => getDefaultMiddleware().concat(api.middleware),
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

```ts
// src/core/store/hooks.ts
import { useDispatch, useSelector } from 'react-redux';
import type { RootState, AppDispatch } from './index';

export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();
```

```tsx
// app/_layout.tsx
import { Provider } from 'react-redux';
import { Stack } from 'expo-router';
import { store } from '@/core/store';

export default function RootLayout() {
  return (
    <Provider store={store}>
      <Stack />
    </Provider>
  );
}
```

## Consuming State in Components and Routes

```tsx
// app/(app)/_layout.tsx — redirect unauthenticated users at the layout level
import { Redirect, Tabs } from 'expo-router';
import { useAppSelector } from '@/core/store/hooks';

export default function AppLayout() {
  const isAuthenticated = useAppSelector((state) => state.auth.isAuthenticated);
  if (!isAuthenticated) return <Redirect href="/login" />;
  return <Tabs />;
}
```

Select the narrowest slice of state a component needs — selecting a whole slice instead of the one field in use causes re-renders whenever any sibling field on that slice changes.

## Server State: RTK Query

RTK Query works unchanged on React Native — `fetchBaseQuery` uses the global `fetch`, which Expo/Hermes provide. It is the standard for server state here too, superseding manual `useState` + `useEffect` fetch/loading/error juggling.

```ts
// src/core/store/api.ts
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';
import type { AuthUser } from '@/features/auth/types';

export const api = createApi({
  reducerPath: 'api',
  baseQuery: fetchBaseQuery({ baseUrl: process.env.EXPO_PUBLIC_API_URL }),
  tagTypes: ['Profile'],
  endpoints: (build) => ({
    getProfile: build.query<AuthUser, string>({
      query: (userId) => `users/${userId}`,
      providesTags: ['Profile'],
    }),
  }),
});

export const { useGetProfileQuery } = api;
```

```tsx
function ProfileScreen({ userId }: { userId: string }) {
  const { data, isLoading, error } = useGetProfileQuery(userId);

  if (isLoading) return <ActivityIndicator />;
  if (error) return <Text>Failed to load profile</Text>;
  return <Text>{data!.name}</Text>;
}
```

## Persistence

Use **`redux-persist`** with `AsyncStorage` as the storage engine to persist non-sensitive slices (UI preferences, cached non-sensitive profile data) across app restarts:

```ts
import AsyncStorage from '@react-native-async-storage/async-storage';
import { persistReducer, persistStore } from 'redux-persist';

const persistConfig = { key: 'root', storage: AsyncStorage, whitelist: ['preferences'] };
```

**Never put tokens, credentials, or other sensitive data in a persisted slice.** `redux-persist` writes to `AsyncStorage`, which is unencrypted — the existing `best-practices.md` rule ("use `SecureStore` for sensitive data, never `AsyncStorage` for secrets") still applies. Keep auth tokens in `expo-secure-store` and read them into memory (an un-persisted slice, or plain module state) at app start instead of persisting them through Redux.

## Testing

Test slice reducers as pure functions, and components with `@testing-library/react-native` wrapped in a real `Provider` backed by a fresh `configureStore()` per test — same pattern as `react-web`'s `redux.md`.

## Best Practices

Same rules as React Web (`redux.md`) — Immer mutation only inside `createSlice`, derive rather than duplicate state, normalize entity collections, keep non-serializable values (including native handles/refs) out of the store. Additionally:

- **Don't select store state inside a `FlatList`/`FlashList` `renderItem`** unless memoized — a Redux update re-renders the list's subscribed component and can crash 60fps scroll performance. Pass the data down as props instead.

## Directory Placement

Mirrors `react-web`'s layout, adapted to this module's `src/` root (see `directory-structure.md`):

```
src/
  features/auth/
    store/
      authSlice.ts        # createSlice: state, reducers, actions
    services/
      authService.ts       # only if not modeled as an RTK Query endpoint
    types.ts
  core/
    store/
      index.ts              # configureStore, RootState/AppDispatch types
      hooks.ts               # useAppDispatch/useAppSelector
      api.ts                  # createApi — shared RTK Query base
      persist.ts              # redux-persist config (non-sensitive slices only)
```
