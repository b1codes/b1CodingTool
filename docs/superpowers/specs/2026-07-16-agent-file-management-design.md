# Agent File Management — Design Spec

**Date:** 2026-07-16
**Status:** Approved design (pending spec review)
**Scope:** `b1CodingTool` (public tool). Touches `scaffolder.py`, `compiler.py`, `translator.py`, `pair.py`, `pull.py`, `schema.py`, and adds new command surfaces.

---

## 1. Problem

b1 is an agent-agnostic context compiler. Today the generated root file (`CLAUDE.md`/`AGENTS.md`) is a **pure filemap** — every section is a *lazy* pointer ("read this when you need it"). There is **no eager slot**: no way for content to be reliably in-context at the start of every session.

Users need three things the current pipeline can't express:

1. **Eager project rules** — "never do X in this project" guardrails that must be loaded *every* session (a lazy pointer risks the behavior recurring because the agent never opens the file).
2. **A personal/local tier** — per-developer, uncommitted context that is *also* eager, and that b1 can keep in sync per-agent.
3. **Bidirectional sync** — one canonical source of truth that fans out to every agent's native files, plus a guided way to promote a hand-edit made in a generated file *back* into the sources.

The design must serve the **full matrix — Claude Code + Codex + Antigravity** — on every `b1 pair`, and **`GEMINI.md` is retired** (Antigravity reads `AGENTS.md` + `.agents/` natively, making it redundant).

---

## 2. Per-agent mechanics (verified facts this design rests on)

| Agent | Auto-loaded root | Personal/local file | Folder auto-load | Rules-file import? |
|---|---|---|---|---|
| **Claude Code** | `CLAUDE.md` (**not** `AGENTS.md`) | `CLAUDE.local.md` — additive, gitignored | `.claude/rules/*` eager; `.claude/context/*` via filemap | `@path` (eager, 4 hops) |
| **Codex CLI** | `AGENTS.md` (walks dir tree) | `AGENTS.override.md` — additive, override-wins, gitignored | reads `AGENTS.md` hierarchy only | **none** |
| **Antigravity** | `AGENTS.md` + `.agents/` (native) | **none** (no `.local` convention) | `.agents/rules/*` eager (always-on); `.agents/skills/*` on-demand | **none reliable** |

**Consequences that shape everything below:**

- **Claude is the only odd-one-out** — it reads `CLAUDE.md`, not `AGENTS.md`. Codex + Antigravity read `AGENTS.md` natively, so `AGENTS.md` + `.agents/` is the **universal native source** for 2 of 3 tools.
- **No portable personal file exists.** So b1 must *compile* one per agent (the compiler's whole reason to exist).
- **Imports are unreliable** on Codex *and* Antigravity → the eager mechanism must be **inline** (b1 physically writes content into the files it generates), never `@import`.

*Sources (verified 2026-07-16): [Claude memory docs](https://code.claude.com/docs/en/memory), [Codex custom prompts](https://developers.openai.com/codex/custom-prompts), [Codex #17401 (no import)](https://github.com/openai/codex/issues/17401), [Antigravity rules guide](https://agentpedia.codes/blog/user-rules).*

## 3. Content taxonomy

The eager/lazy split is by **content type**, not by file:

- **Eager** — behavioral rules, guardrails, conventions, edge cases. Small, high-value, must be in-context before the agent acts.
- **Lazy** — bulky reference (module contexts, deep architecture). Safe to load on demand via pointers.

Orthogonally, content has an **ownership/visibility** class:

- **Shared** (committed) — team project rules + public module pointers.
- **Personal** (gitignored, per-developer) — individual notes/overrides.
- **Proprietary** (gitignored, per-install) — `llc-`/`proprietary: true` module pointers. Rides the *same gitignored channel as personal* because from this repo's git perspective it is not committable, and it is materialized per-machine by whoever has the private overlay installed.

## 4. Source files (seeds) — created by `b1 init`

`b1 init` scaffolds the authoring surfaces the user (or a slash command) edits. Users **never hand-edit the generated outputs** in §5.

| Seed | Committed? | Tier | Purpose |
|---|---|---|---|
| `AGENTS.md` (root) | ✅ committed | — | **Fully b1-managed OUTPUT**, but also the committed universal master. Wholesale-regenerated by the compiler (see §5). Contains shared rules (inlined) + **public** module pointers. Users don't edit it directly. |
| `.agents/project/AGENTS.md` | ✅ committed | Eager, shared | Authoring surface for shared project rules & edge cases. Compiled into root `AGENTS.md` + `CLAUDE.md`. |
| `.agents/local/AGENTS.md` | ❌ gitignored | Eager, personal | Authoring surface for personal rules & edge cases. Compiled **only** into the gitignored per-tool files — **never** into committed `AGENTS.md`. |

`b1 init` also adds `.gitignore` entries for `.agents/local/`, `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.override.md`, `.claude/`, `.agents/rules/local.md`, and the drift snapshot dir (§7).

> **Agnostic-tier reconciliation (decided 2026-07-16):** today `context_manager.py` authors root `AGENTS.md` as a *project-agnostic source* and the compiler reads it as one. Under this design **root `AGENTS.md` is a generated output, not a source** — so the agnostic tier is **folded into `.agents/project/AGENTS.md`** (one shared authoring surface). On upgrade, any existing authored root `AGENTS.md` content is **migrated** into `.agents/project/AGENTS.md` before root `AGENTS.md` is first regenerated, so no user content is clobbered. Project-agnostic baselines are better served by modules or `~/.claude` going forward.

> **Naming note:** the two seed files are named `AGENTS.md` inside `.agents/project/` and `.agents/local/`. These live in non-code subdirectories, so no agent's native hierarchical discovery auto-reads them (Codex walks ancestor dirs from code; Antigravity reads root + `.agents/rules/` + `.agents/skills/`). Accepted per user preference.

## 5. `b1 pair` fan-out — the full matrix

Root `AGENTS.md` is **fully b1-managed and wholesale-regenerated** (like `CLAUDE.md`). This retires the fragile `<!-- b1:managed -->` marker-splice approach and permanently resolves the original source-vs-output collision (the file is no longer both an input and an output — it is purely an output; the inputs are the `.agents/` seeds).

**Compile inputs → outputs:**

| | `.agents/project/AGENTS.md` (eager shared) | `.agents/local/AGENTS.md` (eager personal) | Public modules (lazy) | Proprietary modules (lazy) |
|---|---|---|---|---|
| **Root `AGENTS.md`** (committed) | inlined | — (excluded: no leak) | pointers | — (excluded: no dangling/leak) |
| **Antigravity** | native read of root `AGENTS.md` | b1 writes `.agents/rules/local.md` (eager, gitignored) | pointers in root `AGENTS.md` | pointers in `.agents/rules/local.md` |
| **Codex** | native read of root `AGENTS.md` | b1 writes `AGENTS.override.md` (gitignored) | pointers in root `AGENTS.md` | pointers in `AGENTS.override.md` |
| **Claude** | inlined into `CLAUDE.md` | b1 writes `CLAUDE.local.md` (gitignored) | filemap → `.claude/context/` | filemap in `CLAUDE.md`/`.claude/context/` (gitignored) |

**Invariants:**
- Native readers (Codex, Antigravity) need **zero generated shared files** — they read committed root `AGENTS.md`. b1 only generates their *personal/proprietary* gitignored vehicles.
- Eager content is always **inlined**, never imported.
- Committed root `AGENTS.md` = public + shared only, so it is stable across machines regardless of who has proprietary overlays or personal notes.

### `b1 pair --sync`

Forward sync across the **entire** supported matrix (not just `active_agents`), guaranteeing parity no matter which agent a teammate opens. Regenerates every service's files from the canonical sources. **Subject to the drift-halt invariant (§7).**

## 6. Slash commands

The work lives in **`b1` CLI subcommands** (one implementation); slash commands are thin per-agent shims generated by `b1 pair` where the surface is solid.

### 6.1 `b1 rule` — record a recurring-bug/behavior guardrail *(centerpiece)*

This is the ergonomic front door to the eager tier: "record a recurring-bug rule" == "get this into the always-loaded context of all three agents."

- **CLI:** `b1 rule "<rule text>" [--scope project|local]` (default `project`).
- **Behavior:** append the rule under a `## Guardrails` section of the destination seed (`.agents/project/AGENTS.md` or `.agents/local/AGENTS.md`), then run the compile, then confirm to the user that it is now eager in Claude, Codex, and Antigravity.
- **Agent shim:** the slash command asks the agent to summarize the recurring behavior into a concise rule from conversation context, then invoke `b1 rule`.

### 6.2 `b1 edge-case` — record a project-specific edge case

- **CLI:** `b1 edge-case "<text>" [--scope project|local]`. **If `--scope` is omitted, prompt the user** for local vs project.
- **Behavior:** append under a `## Edge cases` section of the destination seed, then compile + confirm.

Both commands share one helper: `append to destination seed → compile → confirm`.

### 6.3 Cross-agent surfacing

| Agent | Shim location | Status |
|---|---|---|
| Claude Code | `.claude/commands/b1-rule.md`, `.claude/commands/b1-edge-case.md` | ✅ confirmed mechanism |
| Antigravity | `.agents/skills/b1-rule.md` (→ `/b1-rule` in TUI) | ✅ confirmed (skills = slash commands) |
| Codex | **TBD** — Codex custom prompts are home-dir-scoped + deprecated; OpenAI recommends **Skills**. v1 surfaces the `b1` CLI as the fallback for Codex users; a Codex Skill shim is a follow-up. | ⚠️ TBD |

## 7. Reverse sync + the drift-safety invariant

### 7.1 Drift-safety invariant (load-bearing)

**No write path (`pair`, `pull`, `pair --sync`) may overwrite a generated file that differs from its stored snapshot.** On every generate, b1 writes a per-file snapshot (content hash + copy) under `.agents/.b1-snapshots/` (gitignored). Before overwriting any generated file, b1 compares on-disk content to its snapshot:

- **No drift** → overwrite normally.
- **Drift detected** (the file was hand-edited) → **halt** that file and route the user to reverse-sync (`/b1-reconcile`). Forward sync must never silently destroy the exact hand-edits reverse-sync exists to rescue.

### 7.2 `/b1-reconcile` — guided reverse sync (skill/dialogue)

Promotes hand-edits made in generated/agent-owned files back into the canonical seeds, then re-fans-out. It must be a **dialogue** because b1 cannot infer *intent* from a diff hunk.

**Flow:**
1. Diff each generated file against its snapshot to isolate manual changes.
2. For each change, show the hunk and ask where it belongs:
   - **Shared rule** → `.agents/project/AGENTS.md`
   - **Personal** → `.agents/local/AGENTS.md`
   - **Discard** (revert to generated)
3. Write to the chosen seed, then compile (fan out to all agents), then refresh snapshots.

Files that are *strictly* managed (root `AGENTS.md`) are flagged as **must-promote** — a direct edit there cannot persist as-is and the dialogue explains why.

**v1 scope (YAGNI):** the "keep this edit in `CLAUDE.md` only, forever" agent-specific-override tier is **out of scope**. Documented as a future `.agents/overrides/<AGENT>.md` source; not built in v1 (nobody requested per-agent-permanent edits).

## 8. `b1 pull` changes

`b1 pull` today only re-fetches module *sources* — it never calls the compiler, so it doesn't rewrite `AGENTS.md`. Fix:

- After fetching upstream module updates, `b1 pull` **prompts `[y/N]` "Re-pair now to apply updates?"** as an optional last step. On `y`, it runs the compile (respecting the §7 drift-halt invariant). This makes "pull updates `AGENTS.md`" literally true without a second manual command.

## 9. Files to touch (implementation surface)

- `commands/init.py` / `core/scaffolder.py` — scaffold `AGENTS.md`, `.agents/project/AGENTS.md`, `.agents/local/AGENTS.md`; expand `.gitignore`.
- `core/compiler.py` — compile from the new seed hierarchy; separate **eager (inline)** vs **lazy (pointer)** content; partition module pointers **public vs proprietary** using the `proprietary`/prefix flag.
- `core/translator.py` — emit the per-agent matrix in §5 (inline eager, personal/proprietary → gitignored vehicles), write per-file snapshots (§7), drop `GEMINI.md`, generate slash-command shims (§6.3).
- `commands/pair.py` — add `--sync`; enforce drift-halt before every write.
- `commands/pull.py` — add optional post-pull re-pair prompt.
- New: `commands/rule.py`, `commands/edge_case.py`, `commands/reconcile.py` (+ `/b1-reconcile` skill).
- `core/schema.py` — confirm `proprietary` flag is exposed to the compiler for pointer routing.

---

## 10. How this closes the loop

The failure the user probed — a recurring-behavior guardrail silently recurring because it was lazy — is answered end to end: `b1 rule` writes the guardrail to the eager tier, the compiler inlines it into the always-loaded context of **all three agents**, `--sync` keeps every agent in parity, drift-safety prevents a stray `pair` from destroying a hand-edit, and `/b1-reconcile` promotes hand-edits back to the canonical source. One source of truth, fanned out natively per agent, with a safe bidirectional bridge.
